4 — What the two renders cannot agree on

  1. Nothing here is authoritative about Roblox. The harness block at the top of this file is five guesses about GuiObject defaults (box, border-box, positioning context, no flex shrink, vertically centred text). Where this render and Roblox differ, suspect those first.
  2. opacity: .97 on .panel composites differently. CSS opacity applies to the whole subtree, so panel text is 97% opaque too; Roblox BackgroundTransparency touches only the fill. Every panel is affected.
  3. .resource eats its bar's padding. Measured here: the bar is 620×76 with 16px of vertical padding, leaving a 44px content box, and the column inside resolves to 68.5px (28px head + 6px track + 17.7px income + two 8px gaps). Centred, it runs from y=3.75 to y=72.25, so it stays inside the plate but the 16px padding buys nothing. Whether Roblox clips, overflows or grows the bar depends on what outlass does with height: auto — probably the single most useful thing to diff.
  4. Text that does not fit. A .build-option is 76px wide with 8px padding, so its content box is 60px; "Construction Bot" at 12px bold measures 63px and, because the option centres rather than stretches its children, it overflows by 3px on each side instead of wrapping. Where text does wrap — .build-hint at 244px — Roblox lays lines out at the font's own height while the browser adds its normal leading of about 1.2, so multi-line boxes will not agree on height either.
  5. -webkit-text-stroke is approximated. The sheet writes the property both sides understand, but Roblox strokes a glyph outward where the browser centres the stroke on the outline, so paint-order: stroke fill is doing the work of keeping it behind the glyph. Expect the browser's to read slightly heavier.
  6. @priority 20 on .stalling does nothing here. It is commented out. The browser gets the same result anyway, by source order: .stalling comes after .resource-amount at equal specificity.
  7. The hazard stripes are a 16-keypoint expansion. Both sides read the same repeating-linear-gradient: the browser renders it natively, while outlass writes the pattern out stop by stop into a UIGradient, which caps at 20 keypoints. Both interpolate in sRGB, so the colour ramps should match closely — the stop positions are the thing to check.
  8. @include seam is never called. The mixin is defined in _mixins.scss and no rule uses it, so there is nothing to render and nothing to compare.
  9. .metal-fill is referenced but undefined. resource_bar.luau tags the metal fill resource-fill metal-fill; only .energy-fill exists as a rule. Harmless — .resource-fill is already the metal tone — but the class name suggests a rule that is not there.
  10. Hover and press states only exist here. .queue-chip and .build-option come from @include cell, which has :hover, :active and :disabled. Nothing in the components is ever disabled, so that branch is untested on both sides.
